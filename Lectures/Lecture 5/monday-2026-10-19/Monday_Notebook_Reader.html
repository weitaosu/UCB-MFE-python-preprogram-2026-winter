D02 · Mutation, reassignment, identity

Core · about 6 minutes

After append, which names see 30? After b is reassigned, do a and b still refer to the same list?
a = [10, 20]
b = a
c = a.copy()
print('Before:', a == c, a is c, a is b)
b.append(30)
print('After mutation:', a, b, c)
b = [99]
print('After reassignment:', a, b, a is b)
assert a == [10, 20, 30] and c == [10, 20]
Before: True False True
After mutation: [10, 20, 30] [10, 20, 30] [10, 20]
After reassignment: [10, 20, 30] [99] False
Instructor answer and teaching notes

Before: True False True. Mutation: a and b both show [10, 20, 30], while c is [10, 20]. Reassignment changes what b names; a stays [10, 20, 30]. == compares values; is compares identity.

Use the phrase “two names, one object.” A Python name binding is a logical relationship. Do not claim id() is a portable physical RAM address. Connect shared references to surprising changes in research code.

D03 · A shallow copy keeps nested references

Core · about 4 minutes

Does copying the outer dictionary isolate the inner list?
from copy import deepcopy
original = {'prices': [100.0, 101.0]}
shallow = original.copy()
independent = deepcopy(original)
shallow['prices'].append(102.0)
print('Original:', original['prices'])
print('Deep copy:', independent['prices'])
print('Shared inner list:', shallow['prices'] is original['prices'])
assert independent['prices'] == [100.0, 101.0]
Original: [100.0, 101.0, 102.0]
Deep copy: [100.0, 101.0]
Shared inner list: True
Instructor answer and teaching notes

The original becomes [100.0, 101.0, 102.0]. The deep copy remains [100.0, 101.0]. The inner list is shared by original and shallow.

Copy depth follows the structure you need to isolate. Deep copying may cost time and memory and is not a universal fix. Keep this to one nested container.

D04 · Mutable defaults

Optional · about 3 minutes

Why does the second call contain both tickers?
def add_ticker(ticker, tickers=[]):
    tickers.append(ticker)
    return tickers

print(add_ticker('AAPL'))
print(add_ticker('MSFT'))

def add_ticker_safely(ticker, tickers=None):
    if tickers is None:
        tickers = []
    tickers.append(ticker)
    return tickers

print(add_ticker_safely('AAPL'))

['AAPL', 'MSFT']
['AAPL']
['MSFT']
Instructor answer and teaching notes

The default list is created once when def executes, so the calls share it. The corrected version creates a fresh list when the argument is omitted. If a caller explicitly passes a list, the corrected function still mutates that supplied list.

D05 · A calculation with explicit inputs

Core · about 5 minutes

What is the value? What should happen if one price is missing?
from math import isclose

def portfolio_value(positions, prices):
    missing = set(positions) - set(prices)
    if missing:
        raise ValueError(f'Missing prices: {sorted(missing)}')
    return sum(shares * prices[ticker]
               for ticker, shares in positions.items())

holdings = {'AAPL': 2, 'MSFT': 1}
prices = {'AAPL': 100.0, 'MSFT': 200.0}
print('Value:', portfolio_value(holdings, prices))
assert isclose(portfolio_value(holdings, prices), 400.0)
assert holdings == {'AAPL': 2, 'MSFT': 1}
try:
    portfolio_value(holdings, {'AAPL': 100.0})
except ValueError as error:
    print('Expected failure:', error)
Value: 400.0
Expected failure: Missing prices: ['MSFT']
Instructor answer and teaching notes

400.0. A missing MSFT price raises a specific ValueError. The calculation returns a value without modifying its input dictionaries. The instructor supplies the known-answer check independently of the implementation.

Name the contract before the code: holdings and matching prices in one currency; value out; missing coverage is an error. This small example checks coverage, not every production concern such as timestamps or currency conversion.

D07 · A timing decorator

Core · about 4 minutes

Does the decorated function still return 400? Which code handles timing?
from functools import wraps
from time import perf_counter

def timed(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        start = perf_counter()
        result = function(*args, **kwargs)
        elapsed_ms = (perf_counter() - start) * 1000
        print(f'{function.__name__}: {elapsed_ms:.3f} ms')
        return result
    return wrapper

@timed
def position_value(shares, price):
    return shares * price

print('Returned:', position_value(2, 200.0))
assert position_value.__name__ == 'position_value'
position_value: 0.000 ms
Returned: 400.0
Instructor answer and teaching notes

The return value is 400.0. The wrapper measures elapsed time and returns the original result. @timed is equivalent to rebinding position_value = timed(position_value). wraps preserves useful metadata. Exact elapsed time varies.

The goal is reading this pattern, not memorizing nested syntax. This simple wrapper reports successful calls; it does not report timing if the function raises. Logging itself is a side effect.

D08 · Classes and independent instance state

class Position:

The values are 300 and 200. first and second hold distinct instance state. self names the instance receiving the method call. asset_type is a class attribute.

D10 · Composition: a portfolio has positions

Core · about 6 minutes

Which object knows how to value one position? Which object combines the results?
class Position:
    def __init__(self, ticker, shares):
        self.ticker = ticker
        self.shares = shares

    def market_value(self, price):
        return self.shares * price

class Portfolio:
    def __init__(self, positions):
        self.positions = list(positions)

    def market_value(self, prices):
        return sum(p.market_value(prices[p.ticker])
                   for p in self.positions)

    def __len__(self):
        return len(self.positions)

book = Portfolio([Position('AAPL', 2), Position('MSFT', 1)])
print('Positions:', len(book))
print('Value:', book.market_value({'AAPL': 100, 'MSFT': 200}))
assert len(book) == 2
Positions: 2
Value: 400
Instructor answer and teaching notes

Position values itself at a supplied price. Portfolio holds positions and aggregates their values. len(book) returns 2 via __len__. This is a has-a relationship.

The list constructor copies the outer container, not the Position objects. That is a deliberate return to reference semantics. A class is useful when related state and behavior belong together; a simple stateless calculation can remain a function.

D11 · A small inheritance example

class Position:

D13 · A generator yields one result at a time

Core · about 5 minutes

Does creating the generator execute its body? What remains after one next call?
def daily_returns(prices):
    for previous, current in zip(prices, prices[1:]):
        yield current / previous - 1

stream = daily_returns([100.0, 110.0, 99.0])
print('First return:', round(next(stream), 3))
print('Remaining:', [round(x, 3) for x in stream])
print('Exhausted:', list(stream))
assert list(stream) == []
First return: 0.1
Remaining: [-0.1]
Exhausted: []
Instructor answer and teaching notes

The body starts when iteration begins. It yields 0.1, then -0.1, then finishes. yield suspends the function and retains its execution state.

This generator makes its outputs lazy, but the input list remains in memory and prices[1:] creates a slice. Do not present it as fully streaming from disk. D14 supplies a cleaner memory comparison.

D14 · Materializing versus streaming

Core · about 5 minutes

Both calculations visit N values. Which needs to retain all of them?
from time import perf_counter
import gc
import tracemalloc

N = 100_000

def measure(function):
    gc.collect()
    tracemalloc.start()
    start = perf_counter()
    result = function()
    elapsed_ms = (perf_counter() - start) * 1000
    _, peak_bytes = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    return result, peak_bytes / (1024 ** 2), elapsed_ms

materialized = measure(lambda: sum([i * i for i in range(N)]))
streamed = measure(lambda: sum(i * i for i in range(N)))
for label, (result, peak_mib, elapsed_ms) in [
    ('list', materialized), ('generator', streamed)
]:
    print(f'{label:9} peak={peak_mib:.3f} MiB  time={elapsed_ms:.1f} ms')
print('Equal answers:', materialized[0] == streamed[0])
assert materialized[0] == streamed[0] == N * (N - 1) * (2 * N - 1) // 6
list      peak=3.815 MiB  time=29.7 ms
generator peak=0.000 MiB  time=28.0 ms
Equal answers: True
Instructor answer and teaching notes

The results agree. The list retains all squared values; the generator supplies them incrementally. Both do O(N) arithmetic. Streaming avoids the O(N) retained collection, but is not guaranteed to run faster.

Measurements are Python allocations observed by tracemalloc, not total process RAM. Instrumentation affects timing. Do not read a universal speed ratio from this tiny example; explain the memory trend.

D15 · Representation changes the memory budget

Core · about 5 minutes

How much element storage do 100,000 float64 values need? What changes with float32?
import numpy as np
import sys

N = 100_000
values = [float(i) for i in range(N)]
wide = np.array(values, dtype=np.float64)
narrow = wide.astype(np.float32)
list_estimate = sys.getsizeof(values) + sum(sys.getsizeof(x) for x in values)
print(f'List + distinct floats, approximate: {list_estimate:,} bytes')
print(f'float64 element buffer: {wide.nbytes:,} bytes')
print(f'float32 element buffer: {narrow.nbytes:,} bytes')
print('0.1 represented as float32:', format(float(np.float32(0.1)), '.17g'))
assert wide.nbytes == N * 8 and narrow.nbytes == N * 4
List + distinct floats, approximate: 3,200,984 bytes
float64 element buffer: 800,000 bytes
float32 element buffer: 400,000 bytes
0.1 represented as float32: 0.10000000149011612
Instructor answer and teaching notes

float64 uses 800,000 element-buffer bytes and float32 uses 400,000. The list estimate includes its references and the distinct float objects created here. NumPy nbytes excludes array-object metadata. Lower precision changes representable values and rounding.

Compare the units and accounting boundaries, not only the totals. Numeric NumPy arrays store fixed-width elements contiguously in this example. Do not claim all arrays are contiguous or all lower precision is acceptable in financial calculations.

D16 · Caching reuses work

Core · about 4 minutes

How many times does the function body run? What happens when its hidden rate changes?
from functools import lru_cache

rate = 0.05
executions = 0

@lru_cache(maxsize=16)
def discounted_value(amount, years):
    global executions
    executions += 1
    return amount / (1 + rate) ** years

print(round(discounted_value(110, 2), 2))
print(round(discounted_value(110, 2), 2))
rate = 0.10
print('After hidden rate change:', round(discounted_value(110, 2), 2))
print('Body executions:', executions)
print('Cache:', discounted_value.cache_info())

@lru_cache(maxsize=16)
def explicit_discounted_value(amount, years, rate):
    return amount / (1 + rate) ** years

print('Explicit new rate:', round(explicit_discounted_value(110, 2, 0.10), 2))
assert executions == 1
assert round(explicit_discounted_value(110, 2, 0.10), 2) == 90.91
99.77
99.77
After hidden rate change: 99.77
Body executions: 1
Cache: CacheInfo(hits=2, misses=1, maxsize=16, currsize=1)
Explicit new rate: 90.91
Instructor answer and teaching notes

The body executes once. All three initial calls return about 99.77 because the cache key contains amount and years, not the global rate. Passing the rate explicitly makes the changed dependency part of the key; the corrected result is 90.91.

Cache hits trade retained memory for avoided work. Cached arguments must be hashable. This example deliberately combines a hidden global and caching to make stale results visible. A CPU cache and a KV cache store different information.

D17 · A Python loop and a NumPy operation

Optional · about 3 minutes

Will NumPy use a GPU here? Does faster arithmetic prove the whole program is faster?
import numpy as np
from time import perf_counter
from statistics import median

values = [float(i) for i in range(100_000)]
array = np.array(values, dtype=np.float64)

def loop_total():
    return sum(x * x for x in values)

def array_total():
    return float(np.sum(array * array))

def median_ms(function):
    samples = []
    for _ in range(5):
        start = perf_counter()
        function()
        samples.append((perf_counter() - start) * 1000)
    return median(samples)

assert np.isclose(loop_total(), array_total())
print('Loop ms:', round(median_ms(loop_total), 3))
print('NumPy ms:', round(median_ms(array_total), 3))
print('Array construction is outside the timed region.')
Loop ms: 1.809
NumPy ms: 0.03
Array construction is outside the timed region.
Instructor answer and teaching notes

This ordinary NumPy example runs on the CPU. Its numerical work executes in compiled routines, reducing Python-level overhead. Array construction is excluded, and the array multiplication creates a temporary. Exact speed ratios depend on the system.

Optional. Useful if students assume NumPy automatically means GPU or parallelism. Compare equivalent outputs before timings; state precisely what the timed region includes.

D18 · A Python function as an agent tool

Core · about 6 minutes

Which component proposes the arguments? Which component actually runs Python? What happens to invalid input?
import math

# Long-only, single-currency classroom example. Type hints are not validation.
def position_value(shares: float, price: float) -> float:
    for name, value in [('shares', shares), ('price', price)]:
        if isinstance(value, bool) or not isinstance(value, (int, float)):
            raise ValueError(f'{name} must be a number')
        if not math.isfinite(value) or value < 0:
            raise ValueError(f'{name} must be finite and nonnegative')
    result = shares * price
    if not math.isfinite(result):
        raise ValueError('position value overflow')
    return result

# Illustrative request, authored for class. No model or network call occurs.
request = {'tool': 'position_value', 'arguments': {'shares': 2, 'price': 100.0}}
tools = {'position_value': position_value}
value = tools[request['tool']](**request['arguments'])
print({'status': 'ok', 'value': value, 'currency': 'USD'})

for arguments in [{'shares': -2, 'price': 100.0}, {'shares': 2, 'price': float('nan')}]:
    try:
        tools['position_value'](**arguments)
    except ValueError as error:
        print({'status': 'error', 'message': str(error)})
assert value == 200.0
{'status': 'ok', 'value': 200.0, 'currency': 'USD'}
{'status': 'error', 'message': 'shares must be finite and nonnegative'}
{'status': 'error', 'message': 'price must be finite and nonnegative'}
Instructor answer and teaching notes

In a real agent, a model may propose a tool name and arguments; the harness validates/dispatches and executes the function. Here a prepared dictionary stands in for the request. Valid input returns 200.0. Negative shares and NaN fail under this deliberately long-only contract.

Trace request, dispatch, function, result. This is a tiny dispatcher, not a production harness. Validation remains necessary even with type hints. Short positions would require a different contract; negative shares are not universally invalid finance data.

D19 · Independent checks catch a plausible defect

Core · about 6 minutes

A function returns a number without crashing. What evidence would show that it is wrong?
from math import isclose

# Reference answers are defined independently of either candidate.
CASES = [
    ('ordinary', 2, 100.0, 200.0),
    ('zero holdings', 0, 100.0, 0.0),
    ('fractional', 0.5, 80.0, 40.0),
]

def candidate_bad(shares, price):
    return shares + price

def candidate_fixed(shares, price):
    return shares * price

def grade(function, cases):
    passed = 0
    for name, shares, price, expected in cases:
        actual = function(shares, price)
        ok = isclose(actual, expected, rel_tol=1e-12, abs_tol=1e-12)
        passed += int(ok)
        print(f'{name}: {"PASS" if ok else "FAIL"}; actual={actual}; expected={expected}')
    return passed

print('Candidate A')
a_passed = grade(candidate_bad, CASES)
print('Candidate B')
b_passed = grade(candidate_fixed, CASES)
assert a_passed == 0 and b_passed == 3
print('Development checks passed:', b_passed, '/', len(CASES))
Candidate A
ordinary: FAIL; actual=102.0; expected=200.0
zero holdings: FAIL; actual=100.0; expected=0.0
fractional: FAIL; actual=80.5; expected=40.0
Candidate B
ordinary: PASS; actual=200.0; expected=200.0
zero holdings: PASS; actual=0.0; expected=0.0
fractional: PASS; actual=40.0; expected=40.0
Development checks passed: 3 / 3
Instructor answer and teaching notes

The faulty addition implementation fails all three checks. Multiplication passes them. The checks assess this arithmetic behavior, not an entire agent’s reliability. The reference answers come from hand-computable cases.

Run A before B; ask students to identify the defect from actual versus expected. A self-check instruction tells an agent what to inspect. An independent grader measures the artifact. Since all cases and code are visible here, these are development checks, not held-out evidence.
